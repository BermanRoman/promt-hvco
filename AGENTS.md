# Работа с HVCO

Для подготовки материала начни с [hvco.md](hvco.md), выбери режим и читай документы по его маршруту; входной контракт и полный процесс не загружаются автоматически для точной короткой правки.

Рассказчик HVCO — клиент мечты, его язык задаёт исследование выбранного сегмента.

Не подключай автоматически авторский голос Романа, Гусара или Ваську из другого проекта.

## Поддержка библиотеки

- Перед изменениями проверяй Git-статус и сохраняй чужую незавершённую работу.
- Методика хранится в `references/`, процесс — в `workflow.md`, входные данные — в `input-contract.md`, роли — в `roles/`.
- Не превращай модельный CustDev в доказательство реальных интервью или покупок.
- Сохраняй восемь секций, две эпифании, практическую пользу и согласование стратегии, если пользователь явно не изменил жанр или процесс.
- Исследования клиентов, черновики, их персональные данные и отчёты заданий хранятся в исключённой из Git папке `runs/` либо вне репозитория.
- Зависимости закреплены по коммитам в `dependencies.json`; не обновляй их незаметно и не копируй соседний runtime в этот репозиторий.
- При изменении контракта проверяй его по указанной версии upstream, а не только по названиям документов.
- После изменения процесса проверь независимым исполнителем поведение на типовом запросе и на существенном недостающем входе.
- Перед push выполни `python3 -m unittest discover -s tests -v`, `python3 scripts/check_dependencies.py`, `git diff --check` и отдельное ревью.

Сборщик текста не публикует материал, а разрешение обновить этот репозиторий не запускает исследование реальных клиентов или внешнюю рассылку.
